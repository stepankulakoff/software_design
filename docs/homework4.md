# Домашняя работа №4

Команды запуска находятся в README. Docker Desktop должен работать.
После сборки запускаются три Java-контейнера: `service1`, `service2` и `client`.
Ранее запущенные вручную Java-программы на портах 8081–8083 нужно остановить.
После изменения кода повторить сборку и пересоздание этих трёх контейнеров.
Не запускайте одновременно локальные и контейнерные серверы с одним ZooKeeper:
они публикуют адреса, доступные в разных сетях.

## Где смотреть

- Grafana: http://localhost:3000/d/currency-homework — логин `admin`, пароль `homework`.
- Prometheus: http://localhost:9090/targets — четыре цели должны иметь статус UP.
- HTTP сервисов: серверы 8081 и 8082, клиент 8083.
- Метрики Spring: `/actuator/prometheus`, состояние: `/actuator/health`, версия: `/actuator/info`.
- ZooKeeper экспортирует свои метрики на внутреннем порту 7070.

Prometheus опрашивает приложения каждые 5 секунд. Дайте ему около минуты после запуска,
чтобы накопить данные для скорости запросов. Настройки источника данных и дашборд
Grafana загружаются автоматически из `monitoring/`. История хранится в Docker volumes.

## Что считается

Actuator/Micrometer собирают JVM-метрики обоих Spring-приложений.
Для ZooKeeper включён встроенный PrometheusMetricsProvider с `exportJvmInfo=true`.
У него другие названия метрик, поэтому дашборд учитывает оба формата.
Видны heap/non-heap память, потоки, загруженные классы, CPU, GC и время работы JVM.
CPU Spring — доля доступных JVM процессоров, ZooKeeper — доля одного ядра.

`RpcMetricsFilter` измеряет каждый HTTP-запрос к `/rpc`, включая ошибки.
Один batch JSON-RPC считается одним HTTP-запросом. Actuator-запросы в этот счётчик не входят.

- `currency_rpc_server_requests_seconds_count`: число запросов с тегами `client` и `status`.
  `rate(...[интервал])` на дашборде даёт запросы в секунду, с разбивкой по серверам и клиентам.
- `currency_rpc_server_errors_total{status="500"}`: число HTTP 500 с запуска процесса.
  Отдельная панель показывает оценку количества за выбранный период через `increase`.
  Этот счётчик начинается с нуля; ошибки JSON-RPC с HTTP 200 не являются HTTP 500.
- `currency_rpc_server_requests_seconds_sum / ..._count` после `rate` даёт среднее время.
- Histogram buckets дают медиану (p50), а переключатель позволяет выбрать p90, p95, p99.
  Перцентили приближённые: вычисляются по корзинам гистограммы.
  При отсутствии запросов время ответа не определено, график может быть пустым.

Клиент передаёт `X-Client-Id` (`CLIENT_ID`, по умолчанию `rate-printer`).
Сервер различает значения из `METRICS_CLIENTS` (по умолчанию `rate-printer,manual`),
остальные попадают в `other`. Для новых клиентов расширьте список на обоих серверах.
Это ограничивает число временных рядов; заголовок не является аутентификацией.
Фильтр клиентов влияет на RPS и длительности, но не на общий счётчик HTTP 500.

## Логи

Клиент и сервер пишут запрос и ответ, HTTP-статус и общий `X-Request-Id`.
Сервер ограничивает тело в логе 8192 байтами и убирает переносы строк.
При ошибке соединения клиент пишет ошибку вместо отсутствующего ответа.
При старте оба приложения выводят версию из Maven build-info и версию Java.
ZooKeeper также выводит свою версию при старте.
Посмотреть: `docker compose logs -f service1 service2 client zookeeper`.
